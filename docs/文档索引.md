### 跨仓库协议

平台仓库负责用户身份、数据版本、任务队列、Worker、配额和报告页面。算法库不读取平台数据库、不访问用户文件路径，也不启动常驻服务。两端只通过结构化请求和结果协议衔接：

```text
平台准备表格和字段绑定
        ↓
算法库 runner_contract 执行一次 operation
        ↓
返回 metrics / tables / charts / presentation / warnings / metadata
        ↓
平台共享渲染器生成网页，按需导出 PDF 或 Word
```

平台侧的完整约束见 [算法库与运行协议](../../DataAnalysisSystem/docs/05-算法库与运行协议.md)、[报告排版协议](../../DataAnalysisSystem/docs/31-算法报告结构与排版协议.md) 和 [算法增量更新方案](../../DataAnalysisSystem/docs/36-算法增量更新与受控代码工作区方案.md)。

## 发布前检查

```powershell
Set-Location D:\project\DataAnalysisAlgorithmLibrary
.\.venv\Scripts\python.exe -m algorithm_cli validate-library packages --json
.\.venv\Scripts\python.exe -m pytest -q
```

新增或修改算法时，必须同时完成 manifest 版本变更、协议校验、代表性数据测试和平台 Worker 环境验证。上传一个新目录不会自动替换已经运行的 Worker；发布记录和回滚以不可变发行版本为单位。

## 目录约定

```text
DataAnalysisAlgorithmLibrary/
├─ algorithm_sdk/       请求、结果、manifest 和报告排版模型
├─ runner_contract/     一次性执行入口和平台适配协议
├─ algorithm_cli/       校验、检查、哈希和诊断命令
├─ algorithm_studio/    可选 PySide6 本地工作台
├─ packages/            完整发行包和 8 个模块
├─ tests/               算法、协议和执行器测试
├─ examples/            脱敏示例和调用样例
└─ docs/                当前说明和本索引
```

`论文模板.docx` 以及个人训练、排版辅助脚本属于本地资料，保持在工作区并由忽略规则保护，不纳入项目发布。
